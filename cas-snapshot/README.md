# 内容寻址快照库（cas-snapshot）

一个**本地**内容寻址快照库练习项目：把逻辑条目切成固定大小的块、按规范化字节
SHA-256 去重保存到应用自己的数据目录，用 SQLite 保存全部元数据，生成可验证的
manifest；实现引用计数、租约/fencing、三阶段冻结与崩溃恢复、代次屏障垃圾回收。
**不连接任何外部存储**。

## 安装 / 演示

```bash
cargo build
cargo test
cargo run -- --listen 127.0.0.1:5243
# 浏览器打开 http://127.0.0.1:5243 ，页面标题为“内容寻址快照库”
```

数据目录默认 `./cas-data`，可用 `--data-dir DIR` 或环境变量 `CAS_DATA_DIR` 指定。
首次启动会预置两个共享块的快照 `snapshot-alpha` / `snapshot-beta`，随即删除
alpha 并执行一次 GC：**beta 仍完整、共享块仍存活、alpha 私有块被回收**，可在
“快照 / 块 / 垃圾回收 / 事件收据”各页核对。

## 数据布局

```
<data-dir>/
  meta.db            # SQLite：块、会话、收据、快照/条目/块、引用集合、意图、事件链
  blocks/<ab>/<cdef…># 内容寻址块文件，路径即摘要（64 位小写 hex）
  tmp/               # 原子落盘临时文件
```

核心不变量：

- 块以规范化字节（原始字节）的 SHA-256 寻址；相同字节只落盘一份，重复上传只新增
  一行**收据**。块先写临时文件、校验摘要后 rename 原子出现。
- 引用计数不是可漂移的计数列，而是 `block_refs(block_hash, ref_id)` 行集合，
  `ref_id` 为 `snap:<快照>` 或 `session:<会话>`；引用数 = 行数。
- **已发布快照引用的每个块都存在且字节重哈希一致**。

## 冻结的三阶段提交与崩溃恢复

`freeze` 顺序：

1. `intent`：写 manifest 意图，快照不可见；
2. `refs`：在一个事务内原子加入该快照对全部块的引用，并把进度推进到 `refs`；
3. `publish`：单事务插入快照/条目/块、删除会话引用、写 `snapshot.frozen` 收据、
   删除 pending。

打开库时自动 `recover()`：

- 停在 `intent`：快照从未可见 → **回滚**意图；
- 停在 `refs`：块齐全 → **继续提交**发布；块缺失 → 删除该快照引用并回滚，
  绝不发布引用不存在块的快照；
- 发布与清 pending 同事务，因此 `after_publish` 崩溃后状态要么没有、要么完整。

崩溃点可注入（测试用）：

```bash
cas-snapshot --data-dir D --crash-point freeze.after_intent|freeze.after_refs|freeze.after_publish \
  crash-freeze --session S --token T --label L --entry NAME FILE
cas-snapshot --data-dir D resume     # 打开即恢复，随后打印并验证
```

## 会话、租约与 fencing token

- 每个会话有单调递增 `fence`；续租换发新 token，旧 token 立即失效。
- 旧 token 的晚提交、过期租约提交、已冻结会话提交一律返回 `409 冲突`。
- 提交支持**幂等键**（会话内唯一）：同键同内容返回原块/原收据；同键不同内容冲突。

## 派生与删除

- 派生以父快照条目为底，应用更新/删除；未变条目直接复用父条目的块引用
  （共享块）。删除父快照只移除 `snap:<父>` 自己的引用，子快照与共享块不受影响。

## 垃圾回收：代次屏障

GC 开始记录“当时最大快照发布序号” `barrier_seq`（即代次）。扫描窗口中若有新快照
冻结（序号 > barrier），即使其块在标记时刻没有引用行，删除事务里的代次屏障检查也会
保留它。每个候选块都在自己的事务内**重查引用计数 + 屏障**后再删元数据和文件。

收据：`gc.started`（含屏障与候选集）、每块 `gc.block_deleted` / `gc.spared`、
`gc.finished`，全部进入哈希链；GC 意图也可崩溃恢复（`gc.resumed`）。

## 验证、篡改与修复

验证重算：块文件摘要/大小、`block_refs` 与条目块集合一致性、manifest 规范化摘要、
事件哈希链。被篡改/缺失块会列出**全部受影响快照**（含共享它的快照）。

- 修复只能**重新上传原始字节**（重算摘要必须等于块名）；内容不同会被拒绝，
  不能悄悄改摘要——改内容应当走新块+新快照。修复产生 `block.repaired` 收据。

## 导出 / 导入

导出包**只含 manifest 与验证证明**（manifest 规范化摘要、`snapshot.frozen` 冻结
收据、导出时事件链头），**不含任何块字节**。导入时重算规范化摘要并核对冻结收据，
纯核对、不写块也不建快照；篡改 manifest 或伪造摘要都会失败。

## 页面

- 快照与 Manifest：manifest、父子关系、代次、删除、派生、共享关系；
- 块 / 共享 / 引用来源：物理占用、每个块的快照/会话引用来源；
- 上传会话 / 租约：token、收据（dedup/new、幂等键）、续租、过期、冻结；
- 验证与修复：最近验证收据、受影响快照、重新上传修复；
- 垃圾回收：代次屏障、开始/逐块/结束收据；
- 导出 / 导入核对；事件收据（哈希链）。

## 测试

`cargo test` 覆盖：重复块只增加收据、多分块共享、幂等键同/异内容、父子派生与
删除、GC 代次扫描竞态、过期/旧 fencing token、手工篡改定位全部受影响快照并修复、
事件链断裂检测、导出无块数据且导入核对、以及三个冻结崩溃点（含 refs 阶段块缺失的
回滚）。
